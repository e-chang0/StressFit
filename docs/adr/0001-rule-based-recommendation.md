# ADR-0001: 첫 버전의 추천은 규칙 기반으로 구현한다

- 날짜: 2026-11-03
- 상태: 채택(추천 데모에 적용, 전체 MVP는 구현 예정)
- 관련 자료: [README의 추천 방식](../../README.md#5-추천-방식mvp), [추천 엔진 이슈](https://github.com/e-chang0/StressFit/issues/6)

## 어떤 상황인가?

StressFit은 운동 경험, 시간, 장소 등에 맞춰 운동을 추천하려고 한다. 아직 사용자 운동 기록이 없고, 학기 안에 설문부터 추천 결과까지 연결해야 한다. 처음부터 학습 모델을 만들면 데이터 수집과 모델 평가에 시간을 많이 쓸 수 있다.

## 비교한 방법

| 방법 | 좋은 점 | 아쉬운 점 |
| --- | --- | --- |
| 조건에 따라 운동 후보를 거르는 규칙 기반 | 데이터가 없어도 시작할 수 있고 추천 이유를 설명하기 쉽다 | 규칙이 많아지면 수정하기 복잡해진다 |
| 사용자 기록으로 학습하는 추천 모델 | 기록이 충분하면 사용자별 차이를 더 반영할 수 있다 | 지금은 학습 데이터와 평가 기준이 부족하다 |

## 결정과 이유

첫 버전은 규칙 기반으로 만든다. 먼저 제외할 운동을 거르고, 남은 후보에서 시간과 장소 등 입력 조건에 맞는 루틴을 고른다. 지금은 복잡한 모델보다 입력부터 추천까지 한 번 제대로 연결하는 것이 우선이라고 판단했다.

현재 `src/recommendation.js`에 입력 검증과 조건 분기를 사용하는 데모가 있다. 이 문서는 README에 적은 방향과 데모의 선택을 정리한 기록이다. 데모의 조건이 실제 운동 적합성이나 효과를 검증했다는 뜻은 아니다.

## 결정 후 할 일과 한계

- 입력 항목과 운동 데이터 형식을 먼저 정한다.
- 규칙을 화면 코드와 분리해서 한곳에서 수정할 수 있게 한다.
- 조건에 맞는 운동이 없으면 임의로 추천하지 않고 입력 조건을 다시 확인하도록 안내한다.
- 실제 운동 적합성 기준은 별도 검토가 필요하다. 스트레스 점수만으로 운동 효과를 단정하지 않는다.

사용 기록이 쌓이고 현재 규칙의 한계가 구체적으로 보이면 모델 기반 방법과 비교한다. 시점만 정해 놓고 바로 모델로 바꾸지는 않는다.

## 확인 방법

현재 데모 테스트는 입력 범위, 시간 제한, 통증 입력의 휴식 안내 등을 확인한다. 전체 MVP에서는 기구가 없는 경우와 후보가 없는 경우도 별도로 테스트할 계획이다. 사용자의 운동 효과나 추천 만족도에 대한 검증 수치는 아직 없다.
