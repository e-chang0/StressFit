# 기술 결정 기록(ADR)

개발하다 보면 왜 이 기술이나 방식을 골랐는지 잊기 쉽다. 나중에 같은 고민을 반복하지 않도록 결정한 이유를 짧게 적는다.

## 작성 방법

1. `0000-template.md`를 복사한다.
2. `0001-rule-based-recommendation.md`처럼 번호와 주제를 붙인다. 번호는 다시 쓰지 않는다.
3. 상황, 비교한 방법, 결정과 아쉬운 점을 적는다.
4. 아직 합의하지 않았으면 `제안`, 결정했으면 `채택`으로 표시한다.
5. 결정을 바꾸면 새 ADR을 만들고 이전 문서 상태를 `대체됨: 새 ADR 링크`로 바꾼다.

토론이 필요하면 [RFC 양식](../community/rfc-template.md)으로 먼저 의견을 모은다. 모든 작은 수정에 ADR을 쓸 필요는 없다. 추천 방식, 데이터베이스, API 구조처럼 다시 바꾸는 데 비용이 드는 결정에 사용한다.
